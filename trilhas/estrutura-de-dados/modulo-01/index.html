Aula 1 de 4

O que é uma estrutura de dados?

Antes do código, precisamos entender qual problema estamos tentando resolver.

Dados precisam de organização.

Um sistema pode precisar guardar nomes de clientes, produtos, notas, pedidos, compromissos ou milhares de outros registros.

Guardar essas informações sem uma forma clara de organização tornaria difícil inserir, procurar, alterar e remover dados.

Estrutura de dados

Uma forma organizada de armazenar dados e definir como podemos trabalhar com eles.

Dados As informações que queremos armazenar.
Organização A forma como os dados ficam relacionados.
Operações Inserir, buscar, remover, consultar e outras ações.
Objetivo Resolver um problema de forma organizada e eficiente.

Um exemplo sem programação.

Imagine uma agenda de contatos. Um contato pode guardar:

Dados 
Nome: Ana
Telefone: 11 99999-9999
Email: ana@email.com

Mas apenas guardar informações não resolve o problema. Também precisamos definir o que pode ser feito com elas.

Operações 
Adicionar contato
Buscar contato
Alterar contato
Remover contato
Listar contatos

Essa relação entre aquilo que guardamos e aquilo que fazemos será importante durante toda a trilha.

Aula 2 de 4

Entendendo TAD.

O nome parece mais complicado que a ideia.

Tipo Abstrato de Dados.

TAD significa Tipo Abstrato de Dados.

TAD

Dados + operações que podem ser realizadas sobre esses dados.

Pense em uma conta bancária.

Dados Saldo, titular e número da conta.
Operações Depositar, sacar e consultar saldo.

Você consegue utilizar uma conta sem conhecer todos os detalhes internos usados pelo banco para armazenar cada informação.

Esse é o papel da abstração: trabalhar com algo sem precisar lidar simultaneamente com todos os detalhes de sua implementação.

Esse padrão aparecerá várias vezes.

Modelo mental 
ESTRUTURA
    |
    +-- DADOS
    |
    +-- OPERAÇÕES

Em uma lista, por exemplo, podemos encontrar operações como:

cria() insere() busca() retira() imprime() libera()

Não tente decorar esses nomes agora.

O que essa estrutura guarda e o que conseguimos fazer com ela?

Aula 3 de 4

Nó, memória e endereço.

Para entender ponteiros, primeiro precisamos saber o que eles apontam.

Pense na memória como locais numerados.

Quando um dado é armazenado na memória, ele ocupa algum local. Esse local possui um endereço.

Memória simplificada 
Endereço 1000  ->  "Ana"
Endereço 1001  ->  27
Endereço 1002  ->  9.5
Endereço 1003  ->  ...

Endereços reais são mais complexos, mas esse modelo é suficiente para compreender o funcionamento das estruturas que estudaremos.

O que é um nó?

Em estruturas encadeadas, os dados costumam ser organizados em pequenas estruturas chamadas nós.

Um nó 
+-----------------------+
|          NÓ           |
+-----------+-----------+
|   info    |   prox    |
+-----------+-----------+
|     A     | endereço  |
+-----------+-----------+
info O dado armazenado no nó.
prox O endereço do próximo nó.
Ligação entre nós 
A  ->  B  ->  C  ->  NULL

O nó A sabe onde B está. B sabe onde C está. C termina em NULL porque não existe um próximo nó.

Então, o que é um ponteiro?

Ponteiro

Uma variável que guarda um endereço de memória.

Ele não precisa armazenar o dado diretamente. Ele pode guardar onde esse dado está.

Ponteiro para um nó 
ponteiro inicio
      |
      | endereço 1000
      v
+-------------+
| Nó A        |
| endereço    |
| 1000        |
+-------------+

Quando encontrar a palavra ponteiro, pense: “uma variável que sabe o endereço de outra coisa”.

Aula 4 de 4

Agora o código começa a fazer sentido.

Em vez de memorizar a sintaxe, vamos traduzi-la.

A estrutura de um nó. 

typedef struct no {
    char info;
    struct no *prox;
} no;
struct no Estamos descrevendo um tipo de estrutura chamado nó.
char info; Dentro do nó existe um campo chamado info.
struct no *prox; prox é um ponteiro capaz de guardar o endereço de outro nó.
typedef ... no; Criamos uma maneira mais curta de chamar esse tipo de estrutura.

O que significa o asterisco? 

struct no *prox;

Nesse contexto, o * indica que prox é um ponteiro.

Tradução

prox não guarda outro nó inteiro. Guarda o endereço de outro nó.

E o operador ->? 

novo->info = 'A';

novo->prox = lista;

Quando temos um ponteiro para uma estrutura, o operador -> permite acessar um campo dela.

novo->info Acesse o campo info do nó apontado por novo.
novo->prox Acesse o campo prox do nó apontado por novo.

NULL. 

novo->prox = NULL;

NULL significa que o ponteiro não está apontando para um endereço válido de outro nó.

Fim da corrente 
A  ->  B  ->  C  ->  NULL

Nesse exemplo, C não possui um próximo elemento.
